# Project growth playbook

Ghost should grow through useful software, reproducible evidence, and respectful promotion—not purchased stars, spam, or exaggerated privacy claims.

## Repository conversion

- Keep the first README screen focused on the problem, the Windows preview status, and a real screenshot.
- Keep the quick-start path short: download, run, test with a second receiver.
- Keep the compatibility matrix current so visitors can see what has actually been tested.
- Publish a release asset and checksum for every version tag.
- Keep CI green and visible through the README status badge.

## Discovery

- Use specific terms that users search for: Windows screen-sharing privacy, Electron capture exclusion, and Windows display affinity.
- Use GitHub topics that describe the project accurately; review them when the product scope changes.
- Link tutorials, release notes, compatibility reports, and contribution paths from the README.
- Add one real screenshot or short demo for each major user workflow. Do not fabricate receiver-side results.

## Launches

For a release, prepare one concise post with:

1. The user problem and who the release helps.
2. A short screen recording or screenshot made from a safe test page.
3. The exact Windows version and capture applications tested.
4. A link to the release, README, and compatibility matrix.
5. One concrete request, such as testing OBS display capture or mixed-DPI monitors.

Relevant communities may include Hacker News, Reddit communities, Dev.to, Product Hunt, and social networks. Follow each community's rules, disclose that you maintain the project, avoid repeated cross-posting, and answer technical questions with evidence.

## Sustainable momentum

- Respond to issues with reproducible next steps.
- Label small, well-scoped tasks as `good first issue` only when they are genuinely ready.
- Thank compatibility testers and contributors in release notes.
- Ship small, meaningful updates rather than empty activity commits.
- Measure release downloads, unique contributors, issue response time, and compatibility reports—not only stars.

Stars and “repository of the week” placement cannot be guaranteed. A clear project, a useful release, and trustworthy evidence are the durable path to visibility.
